Built from hands-on practice on Ubuntu Server 26.04.1. Updated as the plan goes on.

Items marked ⚠️ are ones I got wrong or had to look up in the Day 7 quiz. Permissions explained in depth (Chinese): [permissions-guide.md](permissions-guide.md). Step-by-step setup by topic: [handbook/](handbook/README.md).

## Filesystem hierarchy (FHS)

```
/                  root of the whole tree
├── etc            system configuration (e.g. /etc/netplan, /etc/ssh/sshd_config)
├── var            variable data; logs live in /var/log
├── home           home directories of normal users (/home/admin123 = ~)
├── root           home of the root user (drwx------, only root can enter)
├── tmp            temporary files, writable by everyone
├── usr            programs and libraries (/bin -> usr/bin)
├── boot           kernel and boot files
├── dev            devices exposed as files (disks, NICs)
└── proc, sys      virtual files generated by the kernel in memory (size 0)
```

Useful logs in `/var/log`:

| File | Content |
|---|---|
| `syslog` | general system log |
| `auth.log` | logins, SSH, `sudo` |
| `kern.log` | kernel messages |
| `dpkg.log`, `apt/` | package installs |
| `wtmp`, `btmp` | binary login records, read with `last` / `sudo lastb` |

Rotated logs: `x.log` is newest, then `x.log.1`, `x.log.2`, ...

## Reading the prompt and `ls -l`

```
admin123@admin:/etc$ cd ..
└ user ┘ └host┘└cwd┘  └ what I typed ┘      $ = normal user, # = root
```

```
drwxr-xr-x 109 root root 4096 Oct 29 07:32 etc
type+perms links owner group size  mtime   name
```

First character: `d` directory, `-` regular file, `l` symbolic link.

## Paths

| Path | Meaning |
|---|---|
| `/etc/ssh` | **absolute**: starts with `/`, same result from anywhere |
| `ssh` | **relative**: resolved as *current dir* + `/ssh` |
| `.` | current directory |
| `..` | parent directory |
| `~` | my home directory |
| `-` (with `cd`) | previous directory |

Example: in `/` `cd etc` works, in `~` `cd etc` fails (`/home/admin123/etc` does not exist), `cd /etc` works everywhere.

⚠️ **Look at the first character.** `/` = start from the very top of the disk. Anything else = start from where I am now.

| I typed (in `~`) | Linux reads it as | |
|---|---|---|
| `ls -l quiz` | `/home/admin123/quiz` | my folder ✅ |
| `ls -l ~/quiz` | `/home/admin123/quiz` | my folder, works from anywhere ✅ |
| `ls -l /quiz` | `/quiz` (top level of the disk) | **a different place** ❌ |

Day 7: `sudo touch /quiz` silently created an empty root-owned file at the top of the disk. `sudo` does not warn you; it just does it. Cleaned up with `sudo rm /quiz`. Before any `sudo` command with a path, read the path once.

## Commands

| Command | What it does |
|---|---|
| `pwd` | print current directory |
| `cd /var/log` / `cd ..` / `cd ~` / `cd -` | change directory (absolute / up / home / back) |
| `ls` | list current directory (columns, alphabetical, top-to-bottom) |
| `ls -l` | long format: type, permissions, owner, size, time |
| `ls -a` / `ls -la ~` | include hidden dotfiles (`.bashrc`, `.ssh`) |
| `ls -1` | one name per line |
| `tree ~/quiz` | ⚠️ show a folder as a tree (needs `sudo apt install tree`) |
| `ls -F` | append `/` to directories |
| `cat file` | print file contents |
| `tail -n 5 file` | last 5 lines of a file |
| `mkdir lab` | ⚠️ create a directory (**m**a**k**e **dir**ectory) |
| `mkdir -p a/b/c` | create nested directories in one go |
| `touch a.txt` | create an empty file |
| `echo "text" > b.txt` | write text into a file (**overwrites**) |
| `cp b.txt c.txt` | copy file (source, then destination) |
| `cp b.txt docs/` | copy into a directory, keep the name |
| `mv c.txt notes.txt` | ⚠️ rename (Linux has no rename command: renaming = **moving** to a new name in the same place) |
| `mv notes.txt docs/` | move into a directory (original is gone) |
| `rm -i a.txt` | delete a file, ask first |
| `rm -ri docs` | delete a directory and its contents, ask for each item |
| `find ~ -name "*.txt"` | search recursively by name (`*` = any characters) |
| `find /etc -name "sshd_config" 2>/dev/null` | same, hide `Permission denied` errors |
| `cat /etc/os-release` | distribution and version |
| `last -n 3` | recent logins |
| `sudo cmd` | run one command as root |
| `ls -l /var/log \| grep ^d \| wc -l` | count directories (pipe preview) |

## Gotchas

- No recycle bin: `rm` is permanent. Use `-i` while learning; never run `rm -rf` on `/` or a path you are not sure about.
- Many commands print nothing on success (`mkdir`, `cp`, `mv`). Silence = OK.
- Error format: `program: command: object: reason`. `No such file or directory` usually means a wrong path or wrong current directory.
- `>` overwrites, `>>` appends.

## Users and permissions (Day 3)

| Command | What it does |
|---|---|
| `groups` / `id` / `id alice` | ⚠️ my groups / full user + group ids / someone else's |
| `sudo useradd -m -s /bin/bash alice` | ⚠️ create user; `-m` = **make** the home folder `/home/alice` (Ubuntu skips it otherwise), `-s` = login shell |
| `sudo groupadd dev` | create a group |
| `sudo usermod -aG dev alice` | add user to group (**always `-a`**) |
| `sudo -u alice cmd` | run a command as another user |
| `chmod o-r f` / `chmod g+w f` | remove / add one permission (`u` `g` `o`) |
| `chmod 640 f` | ⚠️ numeric: r=4 w=2 x=1. **Add inside each set, then write the 3 digits side by side** |
| `sudo chown quizuser f` | ⚠️ change the **owner** (ch-own). Always needs `sudo` |
| `sudo chown root:dev /srv/dev` | change owner **and** group (`owner:group`) |
| `sudo chown -R alice:dev dir` | the directory and everything inside |
| `ls -ld dir` | permissions of the directory itself |
| `umask` / `umask 077` | show / set default mask (file = 666 − umask) |

Common modes: `644` file, `600` private file, `755` directory/script, `750` home dir, `770` group-shared dir.

Working out a number (Day 7 mistake: wrote `620` instead of `640`):

```
want      owner rw-   group r--   others ---
add       4+2         4           0
digits    6           4           0     ->  chmod 640 f
```

If a digit comes out as 1, 2 or 3, double-check: real permissions almost always use 0, 4, 5, 6, 7.
Always `ls -l` right after `chmod` / `chown` and compare with what I wanted.

**chmod vs chown:** chmod changes *what people can do* (the 9 letters); chown changes *whose file it is* (the owner column). The 9 letters stay the same after chown.

## Package management with apt (Day 4)

| Command | What it does |
|---|---|
| `sudo apt update` | ⚠️ refresh the list of available packages (installs nothing). Run this **first**, then `install` |
| `apt list --upgradable` | packages with newer versions |
| `apt search tree` | search package names and descriptions |
| `apt show tree` | package details: version, `Installed-Size`, description |
| `sudo apt install tree` | download and install a package |
| `sudo apt remove tree` | uninstall, **keep** config files |
| `sudo apt purge tree` | uninstall **and** delete config files |
| `apt list --installed tree` | is it installed? (no output = not installed) |

Why `sudo`: installing changes the whole system, so only root may do it. `apt show` / `apt search` / `apt list` only read, so no `sudo`.

Long output opens in the `less` pager: `q` quit, Space next page, arrows scroll.

## Viewing text, redirection and pipes (Day 5)

| Command | What it does |
|---|---|
| `cat f` | print the whole file (short files) |
| `head -n 5 f` / `tail -n 5 f` | ⚠️ first / last 5 lines (`-n` = **n**umber of lines). They read the file directly, no `cat` needed |
| `less f` | page through a long file: Space next page, `q` quit |
| `echo "text"` | print the **text itself** (not a file's contents) |
| `cmd > f` | ⚠️ write output to a file, **overwrite** (one arrow = start over) |
| `cmd >> f` | ⚠️ write output to a file, **append** (two arrows = add more) |
| `cmd1 \| cmd2` | pipe: output of `cmd1` becomes input of `cmd2` |
| `grep word` | keep only lines containing `word` (case-sensitive) |
| `grep -v word` | keep only lines **not** containing `word` |
| `wc -l` | count lines |
| `sort` / `sort -r` | sort a–z / reverse |

Examples practiced:

```bash
grep bash /etc/passwd | wc -l              # users who can log in with bash (5)
grep -v nologin /etc/passwd | wc -l        # accounts without nologin (7)
head -n 2 /etc/passwd | tail -n 1          # only line 2
grep CRON /var/log/syslog | tail -n 3      # last 3 cron runs
ls /etc | sort > ~/etc-sorted.txt          # save a result
echo "checked on Nov 3" >> ~/login-users.txt   # add one line
```

`/etc/passwd` format: `name:x:UID:GID:comment:home:shell`. Shell `/usr/sbin/nologin` = service account that cannot log in.

Mistakes I made: typed `touch` for `tail`; used `echo /etc/passwd | grep bash` (prints the words "/etc/passwd", so grep finds nothing — use `cat` or `grep bash /etc/passwd`); used `>>` to save a fresh result (run twice → duplicates; use `>`).

## Editing files: vim and nano (Day 6)

vim has **modes**. Same key = command in Normal mode, text in Insert mode. Not sure where you are? Press `Esc` first.

| Key (vim) | What it does |
|---|---|
| `vim f` | open (or create) a file, starts in **Normal** mode |
| `i` | Insert mode at the cursor (bottom-left shows `-- INSERT --`) |
| `A` | jump to end of line **and** enter Insert mode |
| `o` | open a new line below and enter Insert mode |
| `Esc` | back to Normal mode |
| `h j k l` / arrows | move left, down, up, right |
| `x` | delete one character |
| `dd` | delete the whole line |
| `:w` / `:wq` | save / save and quit |
| `:q!` | quit **without saving** (escape hatch) |

`-- VISUAL --` appearing by itself = I clicked inside vim with the mouse. Press `Esc`.

My `~/.vimrc`:

```vim
set number   " show line numbers
set mouse=   " disable mouse, so clicks don't start Visual mode
```

nano has no modes; `^` = Ctrl. `Ctrl+O` then Enter = save, `Ctrl+X` = exit.

Why still learn vim: `vi`/`vim` exists on almost every server and minimal image; nano often does not.

## Processes (Day 8)

| Command | What it does |
|---|---|
| `ps` | processes in **this terminal** only |
| `ps aux \| grep name` | find a process by name in **all** processes; column 2 = PID; ignore the `grep` line itself |
| `top` | live view sorted by CPU; `q` to quit |
| `cmd &` | run in the background; prints `[1] PID` |
| `kill PID` | send SIGTERM (15, default): "please exit" → `Terminated` |
| `kill -9 PID` | send SIGKILL (9): forced → `Killed`. Use only if 15 doesn't work |
| `yes > /dev/null &` | lab trick: burns one CPU core |
| `> /dev/null` | throw output away ("black hole") |

## Services: systemctl (Day 9)

| Command | What it does |
|---|---|
| `systemctl status svc` | state; `Active:` = running now, `enabled` = starts at boot |
| `sudo systemctl start / stop / restart svc` | now |
| `sudo systemctl enable / disable svc` | at boot (independent of start/stop) |
| `sudo systemctl daemon-reload` | after creating/editing a unit file in `/etc/systemd/system/` |
| `sudo reboot` | restart the VM; the DHCP IP may change afterwards |
| `curl http://localhost` | fetch a web page from the command line |

Unit file skeleton: `[Unit] Description=` · `[Service] ExecStart=/absolute/path` `Restart=always` · `[Install] WantedBy=multi-user.target`. Full walkthrough: [handbook/04-systemd.md](handbook/04-systemd.md).

⚠️ Day 8–9 warm-up: `chown` needed a reminder (`sudo chown owner:group file`). ⚠️ `chmod 755 timestamp.sh` from `~` failed: relative path again → use `/usr/local/bin/timestamp.sh`.

## Shell scripting (Day 10)

| Syntax | Meaning |
|---|---|
| `echo $?` | exit code of the last command: 0 = OK, 127 = command not found |
| `x=value` / `"$x"` | store (no `$`, no spaces) / read (with `$`) |
| `$1` `$2` / `$#` / `$0` | arguments / how many / script name |
| `$(cmd)` | replace with the output of `cmd` |
| `[ -d "$x" ]` `[ -f "$x" ]` `[ -z "$x" ]` | is a directory / is a file / is empty |
| `[ "$a" -gt 80 ]` `-lt` | number greater / less than |
| `[ ! ... ]` | not |
| `if [ ... ]; then ... else ... fi` | branch |
| `for f in dir/*.txt; do ... done` | loop over files |
| `name() { ...; }` | function; `$1` inside = function argument |
| `exit 1` | end the script as failed |
| `tar -czf out.tar.gz dir` | archive + compress a directory |
| `basename /a/b/c.txt` | → `c.txt` |
| `df --output=pcent / \| tail -n 1 \| tr -d ' %'` | disk usage of `/` as a bare number |
| `rmdir dir` | delete an **empty** directory (safer than `rm -r`) |

⚠️ Day 10: forgot `$` when reading a variable (`"dir"`); dropped spaces (`[ -d"$1" ]`, `backup -`); used `mkdir` to "create" a script file (use `nano`/`touch`).

## Logs and troubleshooting (Day 11)

| Command | Meaning |
|---|---|
| `sudo journalctl -u nginx -n 20 --no-pager` | last 20 log lines of a service (`-u` = **service name**) |
| `sudo journalctl -u nginx -b` | since this boot |
| `sudo journalctl -u nginx --since today` | since midnight (`yesterday`, `"1 hour ago"`) |
| `sudo journalctl --since "2026-11-13 06:55" --until "2026-11-13 06:57"` | everything in a time window |
| `sudo journalctl -u nginx -f` | follow live, `Ctrl+C` to stop |
| `sudo nginx -t` | test nginx config **before** restarting |
| `sudo ss -tlnp \| grep :80` | who is listening on port 80 |
| `sudo kill <PID>` / `sudo kill -9 <PID>` | ask a process to exit / force it |
| `cmd &` | run in the background |

⚠️ Day 11: `-u` with a file path → `-- No entries --`; check the **date** of an error line; `chown :group f` (only the group); `chmod` on a root-owned file needs `sudo`; forgot `kill`.

## Text processing (Day 12)

| Command | Meaning |
|---|---|
| `curl http://localhost/` / `curl -s -o /dev/null URL` | fetch a page / quietly, discard the page |
| `for i in $(seq 1 100); do ...; done` | repeat 100 times |
| `grep " 404 " file \| wc -l` | count lines containing ` 404 ` |
| `awk '{print $1}' file` | print field 1 of each line (fields split on spaces) |
| `sort \| uniq -c` | count identical lines (sort first!) |
| `sort -rn \| head -n 3` | biggest numbers first, top 3 |
| `sed 's/old/new/'` | replace text in the output |

nginx access log: `$1` = IP, `$9` = status. Top IP: `awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -n 3`
