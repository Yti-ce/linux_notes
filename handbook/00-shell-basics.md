## 0.1 Filesystem layout (FHS) — Day 2

Linux has **one tree** that starts at `/`. There are no drive letters like `C:`.

```text
/                  root of the whole tree
├── etc            system configuration (/etc/netplan, /etc/ssh/sshd_config, /etc/passwd)
├── var            variable data; logs live in /var/log
├── home           home directories of normal users (/home/admin123 = ~)
├── root           home of the root user (drwx------, only root can enter)
├── srv            data served by this machine (/srv/dev in Chapter 2)
├── tmp            temporary files, writable by everyone
├── usr            programs and libraries (/bin -> usr/bin; my own scripts go in /usr/local/bin)
├── boot           kernel and boot files
├── dev            devices exposed as files (disks, NICs, /dev/null)
└── proc, sys      virtual files generated by the kernel in memory (size 0)
```

Where to look first when something breaks: **config in `/etc`, logs in `/var/log`**.

| File in `/var/log` | Content |
|---|---|
| `syslog` | general system log |
| `auth.log` | logins, SSH, `sudo` |
| `kern.log` | kernel messages |
| `dpkg.log`, `apt/` | package installs |
| `wtmp`, `btmp` | binary login records, read with `last` / `sudo lastb` |

Rotated logs: `x.log` is the newest, then `x.log.1`, `x.log.2`, ...

## 0.2 Reading the prompt and `ls -l` — Day 2

```text
admin123@admin:/etc$ cd ..
└ user ┘ └host┘└cwd┘  └ what I typed ┘      $ = normal user, # = root
```

```text
drwxr-xr-x 109 root root 4096 Oct 29 07:32 etc
type+perms links owner group size  mtime   name
```

First character: `d` directory, `-` regular file, `l` symbolic link. The other 9 characters are the permissions, explained in [Chapter 2](02-permissions.md).

## 0.3 Working with files — Day 2

| Command | What it does |
|---|---|
| `pwd` | print the current directory (check this whenever a path fails) |
| `cd /var/log` / `cd ..` / `cd ~` / `cd -` | go to an absolute path / up one level / home / back to the previous one |
| `ls` / `ls -l` / `ls -la` | list / long format / include hidden dotfiles (`.bashrc`, `.ssh`) |
| `ls -ld dir` | the directory itself, not its contents |
| `tree dir` | show a folder as a tree (`sudo apt install tree`, see [1.6](01-environment.md#16-packages-with-apt)) |
| `mkdir lab` / `mkdir -p a/b/c` | create a directory / nested directories in one go |
| `touch a.txt` | create an empty file |
| `cp b.txt c.txt` / `cp b.txt docs/` | copy (source first, then destination) / copy into a directory |
| `mv c.txt notes.txt` | rename. Linux has no rename command: renaming = **moving** to a new name |
| `mv notes.txt docs/` | move into a directory (the original is gone) |
| `rm -i a.txt` / `rm -ri docs` | delete a file / a directory and its contents, asking first |
| `find ~ -name "*.txt"` | search recursively by name (`*` = any characters) |
| `find /etc -name sshd_config 2>/dev/null` | same, hide `Permission denied` errors |
| `cat /etc/os-release` | distribution and version |

Lab sequence (Day 2):

```bash
cd ~/lab
mkdir docs
touch a.txt
echo "hello" > b.txt
cp b.txt c.txt
mv c.txt notes.txt
mv notes.txt docs/
ls -l . docs
find ~ -name "*.txt"
rm -i a.txt
```

Rules that save trouble:

- **No recycle bin.** `rm` is permanent. Use `-i` while learning; never run `rm -rf` on `/` or on a path you have not read twice.
- **Silence = success.** `mkdir`, `cp`, `mv`, `chmod` print nothing when they work. Check with `ls -l`.
- **Error format:** `program: object: reason`. `No such file or directory` almost always means a wrong path or the wrong current directory → `pwd`.
- **Tab completion** fills in paths and catches typos (`/sev/dev`, `quiz..txt`).

## 0.4 Viewing text — Day 5

| Command | Use it for |
|---|---|
| `cat f` | short files: print everything |
| `head -n 5 f` | first 5 lines (`-n` = **n**umber of lines) |
| `tail -n 5 f` | last 5 lines; newest entries of a log |
| `less f` | long files: Space = next page, `/word` = search, `q` = quit |
| `echo "text"` | print the **text itself**, not a file |

`head`, `tail`, `less` and `grep` read the file directly; no `cat` in front is needed.

`/etc/passwd` (one user per line) is a good file to practice on:

```text
name:x:UID:GID:comment:home:shell
admin123:x:1000:1000:admin123:/home/admin123:/bin/bash
```

Shell `/usr/sbin/nologin` = a service account that cannot log in.

## 0.5 Redirection and pipes — Day 5

| Syntax | Meaning |
|---|---|
| `cmd > f` | write output to a file, **overwrite** (one arrow = start over) |
| `cmd >> f` | write output to a file, **append** (two arrows = add more) |
| `cmd 2>/dev/null` | throw away error messages (`2` = stderr; `/dev/null` = "black hole") |
| `cmd1 \| cmd2` | **pipe**: output of `cmd1` becomes input of `cmd2` |

Filters to put after a pipe:

| Filter | Keeps / does |
|---|---|
| `grep word` | lines containing `word` (case-sensitive) |
| `grep -v word` | lines **not** containing `word` |
| `wc -l` | counts lines |
| `sort` / `sort -r` | sorts a–z / reverse |
| `head -n N` / `tail -n N` | first / last N lines |

Worked examples (my own results on the VM):

```bash
grep bash /etc/passwd | wc -l              # users with a bash login shell → 5
grep -v nologin /etc/passwd | wc -l        # accounts that are not nologin → 7
head -n 2 /etc/passwd | tail -n 1          # only line 2
grep CRON /var/log/syslog | tail -n 3      # last 3 cron runs
ls -l /var/log | grep ^d | wc -l           # number of directories in /var/log
ls /etc | sort > ~/etc-sorted.txt          # save a result (>, so a re-run doesn't duplicate it)
echo "checked on Nov 3" >> ~/login-users.txt   # add one line to an existing file
```

Read a pipeline left to right and check each step on its own first: `grep bash /etc/passwd`, then add `| wc -l`.

## 0.6 Editing files: vim and nano — Day 6

Config files (`/etc/...`, unit files in [Chapter 4](04-systemd.md)) are edited in a terminal editor. Use `sudo` for files outside your home: `sudo vim /etc/...`.

### vim

vim has **modes**: the same key is a command in Normal mode and text in Insert mode (like switching between Chinese and English input). When unsure, press **`Esc`** first.

| Key | What it does |
|---|---|
| `vim f` | open (or create) a file; starts in **Normal** mode |
| `i` | Insert mode at the cursor (bottom-left shows `-- INSERT --`) |
| `A` | jump to end of line **and** enter Insert mode |
| `o` | open a new line below and enter Insert mode |
| `Esc` | back to Normal mode |
| `h j k l` / arrows | move left, down, up, right |
| `x` | delete one character |
| `dd` | delete the whole line |
| `:w` / `:wq` | save / save and quit |
| `:q!` | quit **without saving** (the escape hatch) |

Practice: `vimtutor` (Lesson 1 done on Day 6).

My `~/.vimrc`:

```vim
set number   " show line numbers
set mouse=   " disable mouse, so clicks don't start Visual mode
```

### nano

No modes; type directly. `^` = Ctrl.

| Key | What it does |
|---|---|
| `Ctrl+O`, then Enter | save |
| `Ctrl+X` | exit |

Why still learn vim: `vi`/`vim` exists on almost every server and minimal image; nano often does not.

## 0.7 Mistakes I made (Days 2–7)

| Typed | What happened | Fix |
|---|---|---|
| `cd etc` in `~` | `No such file or directory`: relative path = `/home/admin123/etc` | `cd /etc` |
| `ls -l /quiz` meaning `~/quiz` | looked at the top of the disk | first character `/` = from the top; see [1.7](01-environment.md#17-absolute-vs-relative-paths) |
| `sudo touch /quiz` | created a root-owned file at `/`; `sudo` doesn't warn | `sudo rm /quiz`; read the path before any `sudo` |
| `touch -n 3 /var/log/syslog` | `unexpected argument '-n'`: meant `tail` | an option is rejected → check the command name first |
| `echo /etc/passwd \| grep bash` | empty: `echo` prints the words, not the file | `grep bash /etc/passwd` |
| `>>` to save a fresh result | ran twice → duplicated lines | `>` for "the result", `>>` for "add a line" |
| `head -m 3` | wrong option | `-n` = number of lines |
| vim shows `-- VISUAL --` | mouse click inside vim | `Esc`; `set mouse=` in `~/.vimrc` |
| extra `i` in the file | pressed `i` while already in Insert mode | `Esc`, `dd` on that line, `:wq` |
